# 水衡 Waterline

图上运水解谜游戏。通过开阀平均、关阀隔离，探索红色圆圈能得到的水量，并提交成绩。精确分数计算、157 道官方关卡，以及自由探索水量的玩家创意工坊。

## 本地运行联网版本

需要 Node.js 22 或更新版本、Docker。后端使用 TypeScript、Fastify 和 PostgreSQL。

```sh
npm ci
docker compose -f compose.dev.yaml up -d
```

把 `.env.example` 复制为 `.env`，保留其中本地开发的数据库地址；Windows 可以执行 `Copy-Item .env.example .env`。随后：

```sh
npm run dev
```

打开 http://127.0.0.1:4174 ，通过用户名和密码注册。开发数据库仅开放在回环端口 54329，使用专门的开发密码和持久化卷。

单独体验静态前端可以执行 `npm run dev:offline`，打开 http://127.0.0.1:4173 。静态服务器返回 API 404 时，前端进入本地预览；联网服务故障会提示连接失败，不会悄悄改用本地账号。

## 玩家与工坊

- 用户名即公开玩家 ID。用户名和密码用于注册、登录；密码以带随机盐的 scrypt 保存。会话使用 HttpOnly Cookie，正式环境使用 HTTPS。
- 登录后在「玩家账号 → API Key」创建程序调用密钥。AI 可通过 [AI API](docs/ai-api.md) 操作官方与工坊关卡，自由挑战并与真人混排；[Python 示例](examples/waterline_client.py) 展示完整流程。机器可读契约位于 `/api/ai/v1/openapi.json`。
- 只有点击「提交成绩」才保存关卡记录。每位玩家、每个关卡版本只保存最佳精确水量及其操作序列。同分或更低的提交不替换最佳操作或首次达成时间。刷新、退出或重新进入关卡均从初始水路开始。
- 排名按精确水量降序，相同成绩共用一个名次，下一个不同成绩紧接下一名（1、1、2）。同分玩家在表内按首次提交该成绩的时间排列。
- 提交后解锁该关排行榜。表中显示玩家 ID，排名高于自己的分数由服务端返回 null，界面显示「？」；同名次与更低名次的分数可见。翻页和玩家资料页执行同一规则，其他人的操作序列不公开。
- 自己的最佳操作支持自动动画回放、暂停、逐步播放和退出回放。回放不改写记录，也不能作为当前尝试提交。
- 工坊自动以「玩家ID-序号」命名。序号由后端串行分配，删除后不重复使用。发布不自动提交成绩，不附带参考解法。作品保存在「我的关卡」，作者可以删除自己的作品。
- 搜索玩家 ID 可进入公开资料，查看该玩家的成绩和已发布关卡。更高成绩在资料页同样隐藏。
- 草稿仍自动保存且归账号私有；未同步草稿按账号在本机保留。多设备编辑检查版本，冲突时保留本机修改。旧版未同步尝试仅归档供导出，不会继续上传或恢复。
- 旧正式数据库中的最佳成绩及操作继续保留；旧 progress/completions 表作为历史数据保留，当前玩法不再写入或恢复它们。

## 游戏体验

首页是可自由点击的 WATERLINE 字形水路，每个字母的绿色圆圈带随机初始水位，不设计分圆圈。首页菜单保留「进入游戏」「创意工坊」「关于」；进入游戏打开选关菜单。

官方 157 关按顺序分页展示，每页 24 关。选关采用带浅绿色纸感底色的方框卡片，大字号关卡名下显示「你的最佳成绩」「你的当前排名」，未提交过显示「？」。卡片内不放关卡缩略图，不显示通关数或完成标记。

所有关卡围绕提交成绩进行，没有通关水量、达标图标或自动通关弹窗。第一关首次提交前，以遮罩先突出红色圆圈与阀门，操作结束后突出提交按钮。提交后显示个人最佳的名次，并提供「进入下一关」「重新挑战」「排行榜」。较低或相同成绩明确提示保留最佳一次。

游玩界面保留「返回菜单」，分数／小数和规则入口位于画板下方。圆圈不显示 00、01 等编号，也不显示目标字样。画板节点大小固定，复杂图在小屏幕可滚动查看。开阀后立即显示准确平均值，并用短动效反馈整组的水量变化；关阀只切断连接，不丢水。撤销、重做和重开只影响当前页面。

工坊从空白画布创建，支持添加、移动、连线、删除、整理和编辑历史。红色圆圈由「计分」图标选择；不填写名称，介绍字段为「留给玩家的话」。「试玩」和「发布」是两个独立操作。空白和单节点草稿可保存，但发布必须是有效连通图。工坊精选字段已预留，算法审核及自动选入游戏菜单按后续需求实现。

整体使用本地 Noto Sans SC，字体许可位于 `assets/fonts/`；动效尊重减少动态效果设置。

## 检查与部署

```sh
npm test
npm run check
npm run test:server
npm run build
```

`test:server` 需要 `.env` 中可访问的 PostgreSQL，测试会创建随机命名的独立 schema 并清理自己的测试数据，不修改正式数据。`npm start` 运行编译后的后端，需要通过环境变量提供数据库配置。

生产部署使用 [1Panel / Docker 部署说明](docs/deployment.md)。源码、容器编排与数据库备份步骤均已准备。当前未提供密码找回、管理后台和工坊审核后台；每日挑战保留为后续扩展。

## 文件结构

- `src/engine.js`、`src/game.js`：精确数学引擎、游戏历史和水量规则。
- `src/levels.js`、`src/imported-levels.js`：稳定 ID 与版本号的 157 道官方题。
- `src/graph.js`、`src/editor.js`：SVG 棋盘与编辑器。
- `src/service.js`：离线预览适配器和题目文件工具。
- `src/remote-service.js`：联网缓存、账号切换、版本同步与 SSE。
- `src/app.js`、`src/styles.css`：页面、引导和响应式样式。
- `server/app.ts`：API、会话认证、请求校验和实时推送。
- `server/store.ts`、`server/schema.sql`：持久化、事务与数据库通知。
- `server/workers.ts`、`server/verify-worker.mjs`：精确重放与排序工作线程池。
- `tests/`：游戏规则、同步和 PostgreSQL 集成测试。
